1.2.0 - What is this Website?

Ever Heard of Crowd Dynamics? So this is the field where Crowd is simulated in a given domain. And just like any other model, there are many ways to do that. But this website uses Hughe's Continum Model for simulating the Crowd Flow. And the original paper by hughes' refered this model to be similar to "Thinking Fluids". And this website allows you to solve hughes' Flow problem online. This model is heavily inspired from Fluid Mechanocs, as the authors clearly says that this is infact a special fluid which rather than forces as the cause of motion, has a desire to move in certain direction depending on the Exits, and crowd in front of it.

2.0.0 - Input Files

So I am considering that files to me is like a matrix. An input file will be a matrix of the same size as of the computation domain. And this website will have four inputs. They are Exit Matrix, Inflow-Outflow Matrix, Density Matrix, and finally Obstacle Matrix.

2.1.0 - Exit Matrix

This will be a boolean matrix and this just has the information about where does the exit lies. Where ever there lies the exit, there the value of this matrix will be one and at all the places other than these, value of matrix will be zero.

Another feature that I aim to put in this website is to allow the user be able to change the location of the exit with time. And this means that the csv file created will be having columns: Time, X, Y, Value. And this way in the porgram I will program the position of the exit at each time step. And all the values between them will be interpolated. This looks complicated and I will look at this later.

2.2.0 - Inflow and Outflow Matrix

Information about the inflow and outflow location and the inflow flux will also have to be specified. I will again consider making the CSV file one for the x-flux at the right and left boundary and then the y-flux at top and bottom boundary through at all time step. And this means now the dimension and flux value can also change with time. One good thign about this feature is that the user will be able to solve for unsteady boundary condition.

2.3.0 - Density Matrix

This matrix will contain Information about the density of the matrix at inital time step. And this will allow the user to solve the evacuation problems. Or problems which contain some distribution of Density before the comutation begins. And this will surely be much smaller CSV file compared to others since this matrix will only have information at t = 0.

2.3.1 - Working of Density Matrix

2.4.0 - Obstacle Matrix

This matrix will be a boolean matrix and will be used to know where does the obstacle exist. This file will be used to make another file which will contain information where the fx_negative mjst be set to zero, and then fx_positive and then fy_negative and finally fy_positive must be set to zero. And therefore the boolean file will be used to generate four more CSV Files

2.4.1 - Working of Obstacle Matrix

This section is about how website Front end will be encoded to form which could be sent to the C solver.

Therefore total number of input files that will be generated from the front end will be Exit.csv, Density.csv, Obstacle.csv, and Inflow-Ouflow.csv (4). And the files that will be generated from the above files are :
fx_negative_obstacle.csv, fx_positive_obstacle.csv, fy_negative_obstacle.csv, fy_positive_obstacle.csv (4).
This will all be generated from the front end, and the csv file will be generated from the front end into the directory through Node.js.
